## 一、系统架构

```
                 ┌────────────────────────────────┐
                 │ 基座（平板，贴冰箱旁，无屏）          │
                 │  · 大蘑菇实体按钮（拍=录音键）        │
                 │  · 广域麦克风 + 喇叭（TTS 询问）      │
                 │  · Wi-Fi 上云 + BLE 网关            │
                 │  · dock 位：磁铁 + 充电触点           │
                 └────────────────────────────────┘
                    ↑ BLE 事件        ↑ BLE 回传/充电触点
   ┌───────────────────────┐   ┌───────────────────────┐
   │ 超小蘑菇 ×N（单件门磁）     │   │ 小蘑菇（录音豆）           │
   │ 加速度唤醒 + 姿态判定       │   │ 取下即录（近讲麦）          │
   │ 贴冰箱门/抽屉             │   │ Flash 缓存 + 放回回传      │
   │ CR2450，目标 3 年         │   │ 锂电，dock 触点充电        │
   └───────────────────────┘   └───────────────────────┘
                        云端：DashScope ASR/TTS + DeepSeek + 公众号
```

**无线设计（关键洞察）**：
- 超小蘑菇贴在门/抽屉的**外表面**——即使在门关闭状态也不在金属箱体内，BLE 事件随时可达基座；
- 小蘑菇在冰箱**外**吸附于基座，取下后也在近场使用，BLE 回传无遮挡问题；
- 基座 ESP32 自带 BLE，**直接当网关**，不需要任何额外 hub。

**对标基准**：小米人体传感器 2S = 蓝牙 5.0（Mesh）+ CR2450 + 约 3 年续航（[小米官方 FAQ](https://www.mi.com/hk/support/faq/details/KA-484510)、[评测](https://zhuanlan.zhihu.com/p/662517544)）。我们的超小蘑菇采用同路线（BLE + CR2450 + 3 年目标），基座即网关。

## 二、超小蘑菇：单件门磁方案（双方案）

形态铁律：**单件**（不是门窗传感器的主磁两件套）。干簧管方案因必须两件而被排除。

### 方案 A（主案）：加速度计唤醒 + 姿态判定 —— 用于平开门
- 器件：三轴加速度计，带**运动唤醒中断**（wake-on-motion），静态功耗 1.5~3µA 级（SC7A20 ≈¥1 / LSM6DSO ≈¥6，BOM 见选型表）。
- 逻辑：SoC 深睡；门被推动的瞬间加速度突变 → 中断唤醒 → 读重力向量。关门≈门面竖直，开门≈门转过 90°+，向量差异巨大 → 判开/关 → BLE 广播 → 回睡。
- **功耗预算**（CR2450 标称 620mAh，常温，每天开关 ~20 次）：
  | 项 | 电流 | 占日均 |
  |---|---|---|
  | SoC 深睡（CH592/TLSR8251 类） | ~1.5µA | 主导 |
  | 加速度计唤醒监测 | ~2µA | 次之 |
  | 每次事件（唤醒+判定+广播 3 包） | ~8mA × 60ms | 20 次/天 ≈ 0.003mAh/天 |
  | **日均合计** | **~4µA** | 理论 >10 年；计自放电/低温衰减，**目标 3 年可达** |

### 方案 B（抽屉）：脉冲唤醒 + ToF 测距确认位移
- 难点：抽屉是**平移**，重力向量不变，方案 A 判不了。
- 方案：加速度脉冲唤醒（同 A）→ 唤醒后用 ToF 测距（VL53L0X 级，只在唤醒后几十 ms 通电）测与柜体的距离变化 → 位移 > 阈值 = 开。
- MVP 简化版：接受"拉动即算开"（脉冲唤醒即报事件，不判方向），真机验证后再决定是否上 ToF。

### 通用红线
1. 传感器必须贴**门/抽屉外表面**，禁止贴金属箱体夹层内；
2. CR2450 不可充电、不可反接，电池座选带防反结构；
3. BLE 广播间隔必须可配置（事件即时广播 + 每日心跳包各一套参数），心跳用于基座判断"传感器还活着/电量预警"。

### 位置感知与分区归属（方案，2026-10-02 增补）

目标：用户不开口，系统也知道"开的是哪个门/抽屉、这次放的东西在哪个分区"。

1. **身份登记（安装时，一次性）**：每个超小蘑菇逐门"开门登记"——用户开哪扇门，基座就把当次上报事件的传感器绑定到该门（用户在配套页上确认一次"这是冷藏室门/冷冻抽屉"）。由此自动得知**冰箱有几个门几个抽屉**（配对传感器数 = 事件源数）。
2. **RSSI 指纹辅助**：金属冰箱内单点 RSSI 测距误差大，**不做三角定位**；改用"开门事件 RSSI 指纹"（每传感器多次开门事件的 RSSI 均值±方差聚类）做近/中/远分档，辅助自动预分组、减少人工确认次数。
3. **运行期归属**：某传感器上报"开门" → 基座 TTS 询问 → **本次录音提取的物品自动归属该传感器绑定的分区**（除非用户明说"放冷冻"）。
4. **常识先验**：物品默认位置常识库（蔬菜水果→冷藏，肉/雪糕→冷冻，调味→调味区…），已在云端后端实现（`default_location()`）。
5. **长期习惯学习**：用户纠正（"不对，雪糕在冷藏"）→ 按户存储的物品位置偏好表，覆盖常识先验；未纠正的保持常识。

## 三、小蘑菇（录音豆）

| 模块 | 选型方向 | 说明 |
|---|---|---|
| 取下检测 | dock 磁铁 + 豆内**簧片开关/霍尔** | 纯硬件信号：吸附=待机+充电，脱离=立即开录。零软件判断成本 |
| 麦克风 | 近讲数字麦（ICS-43434 / INMP441 类，I2S） | 近讲收音是它存在的理由，指向性/防风棉在结构上解决 |
| 缓存 | SPI Flash 8~16MB（W25Q64/128 级） | ADPCM 压缩后 ~8KB/s：8MB ≈ 17 分钟，16MB ≈ 34 分钟；"定时回传+放回回传"双保险防撑爆 |
| 回传 | BLE → 基座 | 范围内定时回传（如每 60s 批量一段）+ 放回即全量回传；回传成功才删本地段 |
| 充电 | dock 触点（磁吸对位） | 触点防反接；**风险项：冷冻/冷藏层使用后的冷凝，充电前需干燥判定（结构预留）** |
| 电池 | 微型锂电（401230 级） | 低温性能衰减写入风险清单；冷冻场景使用后回温再充电 |

## 四、基座（平板 + 大蘑菇）

- **MVP 载体 = EasyInput V2 键盘板**：板载 I2S 麦（GPIO9/10/11）、I2S 喇叭（GPIO14/13/15）、KEY1（GPIO2）=拍键、KEY2（GPIO47）=模拟门磁事件、GPIO8 共享外设电源域（录/放前开、用完关，租约模式）、Wi-Fi + BLE 就绪。板级事实以 `easyinput-board-cy` skill 与 `easy-input-maker/docs/hardware/easyinput-v2-safety.md` 为准。
- **最终形态**：ESP32-S3-WROOM-1（Wi-Fi+BLE+双 I2S 余量）+ 大蘑菇机械按键（带按压反馈的"拍"手感，结构重点）+ 广域麦 + 2W 喇叭 + 18650/聚合物锂电 + USB-C；平板外壳 3D 打印，正面 dock 位放小蘑菇。连接表在 PCB 设计阶段（v1）补原理图文件。

## 五、证据分层（继承 easy-input-maker 方法论）

引脚表/选型正确 ≠ 驱动能跑 ≠ 录到数据 ≠ 上传成功 ≠ 云端解析正确 ≠ 公众号收到。每级单独留证据。

## 六、已知风险与开放问题

1. **抽屉单件感知**（方案 B 的 ToF 路线）未经实物验证——MVP 用简化版，v1 打样验证；
2. 小蘑菇**低温冷凝 + 锂电低温**：冷冻场景使用后的充电策略需要结构和使用说明配合；
3. 超小蘑菇 BLE 与基座的**配对/换电池流程**未定义（v1 前定）；
4. 基座喇叭 TTS 与录音共用 GPIO8 电源域：问句播完→开录的切换时序要实测（MVP 阶段在键盘板上验证）；
5. 大蘑菇"拍"的手感与防误拍（关门震动误触发？门磁事件与拍键的仲裁已在交互总纲定义，机械防误拍在结构阶段解决）。
