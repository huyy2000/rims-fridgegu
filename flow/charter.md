# RIMS 录音豆 · Charter

> 所有 Agent 开工要读的第一份。

- **项目名**:RIMS 冰箱菇(FridgePal)
- **目标**(做成什么样算成功,一句话):一套贴在冰箱上的蘑菇三件套——拍大蘑菇随手记、开门基座主动问、拿走小蘑菇边放边记,AI 把冰箱管起来,结果在微信公众号里一眼看清。
- **范围**:
  - 做:①冰箱物品管理(大蘑菇拍键录音 + 门磁事件触发询问录音 + 小蘑菇取下录音 → 统一云端链路 ASR → LLM → 库存表格卡片推送)②出门前购物清单(库存推导 + 对话增删 → 清单卡片推送);微信发消息进来也要识别整理。产品定义见 `冰箱菇_产品定义_v4.md`。
  - 不做:无屏幕、无 BLE 音频流、无唤醒词、无离线 ASR、无多成员、无菜谱;MVP 阶段小蘑菇/超小蘑菇不出实物(纯逻辑组件+硬件文档先行)。
- **约束**(时间 / 资源 / 必须遵守的):
  - MVP 载体 = EasyInput V2 键盘板(`easy-input-maker` 仓库 `rims-mvp` 分支,worktree 在 `D:\easy-input\easy-input-maker-rims`);最终形态 = ESP32-C3 SuperMini 豆(本仓 `firmware/`,暂停至物料到货)。
  - 方法论继承 easy-input-maker:纯逻辑进 `components/`(host 可测)、硬件适配进 `main/platform/`、证据分层、烧录需用户授权。
  - 公众号交付一律图片卡片(SVG 矢量自排 → PNG),不做聊天文字表格。
- **成功标准**(尽量可衡量):实板上「按键录音 → 公众号收到库存卡片」与「开门询问 → 录音 → 库存更新」两大闭环全链路可用;证据分层每级有据可查。
- **角色**:拍板 = 小祜 / 主控 = Claude(WorkBuddy)/ 评审 = 跨模型 / 硬件采购 = 小祜
